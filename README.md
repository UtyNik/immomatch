# ImmoMatch AI

Асинхронный Telegram-бот для поиска жилья в Германии на aiogram 3.x.
Интерфейс на трёх языках: украинский, русский, английский.

## Быстрый старт

1. Создать виртуальное окружение и установить зависимости (команды ниже).
2. Скопировать `.env.example` в `.env` и заполнить `BOT_TOKEN` и `OPENAI_API_KEY`.
3. Запустить: `python bot.py`.

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
python bot.py
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
python bot.py
```

## Сценарий анкеты

`/start` показывает сохранённую анкету, а если её нет — предлагает выбрать язык
и последовательно спрашивает: имя, фамилию, город, радиус поиска (Umkreis),
максимальный бюджет (Warmmiete), минимум комнат, минимальную и максимальную
площадь (Wohnfläche), сколько человек будет жить, есть ли WBS, оплачивается ли
аренда через Jobcenter, домашних животных, чистый доход и свободные пожелания.
Имя, фамилия и город с кириллицы нормализуются в латиницу / официальное немецкое
название (`city_de`) перед сохранением — так Kleinanzeigen и Anschreiben получают
«Freiburg» и «Mykyta Lytvynov», а не «Фрайбург».

Максимальную площадь можно не ограничивать: кнопка «Без ограничений» пишет
в `sqm_max` NULL.

WBS и Jobcenter — разные сущности: сертификат на социальное жильё не значит,
что аренду платит Jobcenter, и наоборот. Поэтому это два отдельных вопроса.

Число жильцов, площадь, имя, раздельные флаги WBS/Jobcenter и радиус появились
позже остальных полей. У тех, кто заполнил анкету раньше, `/start` и поиск
спрашивают только недостающее (имя и фамилию в том числе) и дописывают ответ,
не сбрасывая город, бюджет и остальное.
Новые колонки досоздаются при старте бота (`ALTER TABLE`), поэтому старая
база не ломается. Старое совмещённое поле `wbs_status` не копируется в новые:
один ответ нельзя честно разложить на два.

Под готовой карточкой четыре кнопки:

- **Искать жильё** — запускает поиск (`callback_data="start_search"`).
- **Автопоиск** — включает или выключает фоновую проверку каждые
  `AUTO_SEARCH_INTERVAL_MINUTES` минут (по умолчанию 10). По умолчанию включён.
- **Сменить язык** — меняет только язык интерфейса, ответы остаются на месте.
- **Создать новую анкету** — единственный способ перезапустить опрос.

Фоновый автопоиск (`services/scheduler.py`) обходит пользователей с
`is_auto_search_enabled` и полной анкетой. Совпадения приходят пушем: карточка,
Anschreiben и кнопка «Перейти к объявлению». Если пользователь заблокировал
бота, автопоиск для него выключается. Суточный лимит AI общий с ручным поиском:
исчерпанный лимит в фоне молча пропускается, без спама в чат.

## Поиск объявлений

Запускается тремя способами: кнопкой «🔍 Искать жильё» под полем ввода,
кнопкой под карточкой анкеты и командой `/search` (`/test_search` оставлен
как псевдоним).

Порядок работы:

1. Суточный лимит проверяется до всего остального: незачем ходить на сайт,
   если оценивать всё равно нельзя.
2. Появляется статусное сообщение «Ищу жильё…», город берётся из анкеты,
   со страницы поиска kleinanzeigen.de забираются все карточки (обычно 25).
3. Уже показанные отсеиваются по таблице `seen_apartments`.
4. Дешёвый фильтр отбрасывает объявления дороже бюджета, с недостаточным
   числом комнат или вне диапазона площади — по данным карточки и страницы
   объявления, без обращения к модели. Цена в списке это Kaltmiete, то есть
   не больше Warmmiete: если уже она выше бюджета, страницу качать незачем.
   Неизвестные значения не считаются нарушением: их оценивает AI, у него есть
   текст объявления.
5. Для уцелевших (не более `DETAILS_LIMIT`) грузятся страницы объявлений —
   там настоящая Warmmiete и описание, — после чего фильтр применяется ещё раз.
6. Кандидаты уходят в `gpt-4o-mini` по одному, **перебор прекращается на первом
   подходящем**. Статусное сообщение удаляется, приходит карточка с готовым
   немецким Anschreiben в блоке `<code>` и кнопками «Перейти» и
   «Пропустить / Искать дальше».
7. Отклонённые моделью объявления пользователю не показываются вовсе. Если не
   подошло ни одно, бот предлагает расширить бюджет или изменить требования и
   сообщает, сколько объявлений проверил.

Кнопка «Пропустить / Искать дальше» сразу запускает поиск следующего объекта.
У показанной карточки она при этом исчезает, остаётся только ссылка: иначе
повторное нажатие запускало бы ещё один платный поиск.

Объявление помечается показанным после оценки AI — и подходящее, и
отклонённое, чтобы не платить за его повторную проверку. Отсеянные дешёвым
фильтром не помечаются: если пользователь поднимет бюджет, они снова попадут
в выборку.

### Почему AI не отбраковывает лишнего

Оценка разбита на два обращения к модели: сначала короткое решение, затем
письмо — и только для подошедшего объявления. Одним запросом модель писала
письмо одновременно с оценкой и печатала вердикт раньше рассуждения, из-за чего
отказывала вопреки собственному объяснению («животных нет, поэтому запрет
животных не мешает» — и `match: false`).

В решении модель обязана сначала процитировать фразу из объявления и назвать
поле анкеты, которому та противоречит: `city`, `budget`, `rooms`, `area`,
`household`, `pets`, `wbs`, `jobcenter`, `notes` или `not_a_rental`. Отказ
проверяется в коде (`_reject_is_invalid`) и отменяется, если:

- категории нет в списке — модель сослалась на то, о чём анкета не спрашивает
  (возраст, профессия, семейное положение, когда число жильцов неизвестно);
- цитаты нет в тексте объявления — модель её домыслила;
- категория не сходится с анкетой: запрет животных для того, у кого их нет,
  ссылка на свободные пожелания, когда поле пустое, или ограничение по составу
  жильцов, когда въезжает один человек (ему подходят и «nur Singles», и
  «keine Familien»).

WBS и Jobcenter проверяются порознь:

- «nur mit WBS» / «WBS erforderlich» — отказ, только если `has_wbs` ложно;
- «kein Jobcenter» / «nur Berufstätige» — отказ, только если `uses_jobcenter`
  истинно.

Съём как WG — не квартира для двоих. «WG Vermietung», «WG-Zimmer»,
«Kaltmiete pro Person» отсекаются и дешёвым фильтром, и моделью, если в анкете
от двух комнат или от двух жильцов. Галочка «WG-geeignet» у обычной квартиры
сама по себе ничего не блокирует.

Наличие WBS само по себе никогда не причина отказа. Если объявление молчит
про сертификат или про соцпомощь, соответствующий флаг игнорируется. В письме
WBS упоминается, только если об этом спросили в объявлении; Jobcenter — только
если спросили про него. Частному арендодателю такая строчка нередко стоит
просмотра.

### Расход OpenAI

Один поиск — не более `MAX_AI_CHECKS` проверок (`handlers/search.py`, по
умолчанию 5), а обычно меньше: перебор прекращается на первом совпадении, а
часть объявлений отбрасывается дешёвым фильтром до модели. Проверка — это один
запрос на решение плюс, для подошедшего объявления, второй на письмо.
Ограничители расхода:

- описание объявления обрезается до 4000 символов перед отправкой;
- ответы ограничены `MAX_DECISION_TOKENS` и `MAX_LETTER_TOKENS`
  в `services/ai_agent.py`;
- на пользователя действует суточный лимит обращений `AI_DAILY_LIMIT` из `.env`
  (по умолчанию 20; `0` отключает лимит), счётчик живёт в таблице `ai_usage`
  и сбрасывается по UTC.

Лимит считает попытки, а не удачные ответы: иначе сбой на стороне OpenAI
позволял бы дёргать платный запрос без ограничений.

Парсер зависит от вёрстки чужого сайта. Селекторы (`article.aditem`,
`#viewad-description-text`, `.addetailslist--detail`) вынесены в
`scrapers/kleinanzeigen.py`; если сайт поменяет разметку, в лог попадёт
предупреждение с размером ответа, а команда вернёт понятную ошибку вместо
падения.

## Замечания по эксплуатации

Бот занимает порт `127.0.0.1:47653` как признак «уже запущен»: второй процесс
откажется стартовать. Это защищает от ситуации, когда два polling-клиента
одного бота отбирают апдейты друг у друга и сыплют `TelegramConflictError`.

Состояния анкеты живут в `MemoryStorage`, поэтому при перезапуске бота
незавершённый диалог теряется — пользователю предлагается нажать `/start`.
При переходе на постоянное хранилище состояний менять нужно только
`create_dispatcher()` в `bot.py`.

## Добавление новых хэндлеров

Создай модуль в `handlers/` со своим `router = Router(name="...")` и добавь его
в `get_routers()` в `handlers/__init__.py`. Порядок в списке важен: апдейт
получает первый роутер с подходящим хэндлером.
